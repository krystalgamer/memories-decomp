temporary.** This is the step that closed the gap, and it took two attempts that
each looked like a failure on their own:

- A named scalar temporary per clamp converted eight stores into eight moves and

That sequence is worth keeping because the first step is the kind of result that

telling us the target's shape had two layers, not that the idea was wrong.

**The frame and the saved-register set already match exactly**, which closes the
register-pressure reading of the residual. Both the target and this candidate
use `addiu $sp,$sp,-144` and save the same nine registers, `$ra` and `$s0`
through `$s7`, at the same offsets. So the remaining five missing `move` are not

### Closed this round

**A base pointer for the reference vector is worse, and the two metrics
disagree about it.** The target materialises `addiu $a1,$a1,%lo(D_800F56F0)`
and offsets from it, so holding the array in a local `s32 *` looked like the
obvious transcription. Measured:

| | count | multiset | differing |
| --- | --- | --- | --- |
| direct array indexing | +4 | **18** | 350 |
| local base pointer | **-1** | 21 | 435 |

The raw count prefers the pointer form and the multiset prefers the array form,
and the multiset is the one to follow: the pointer version loses two `lui` and
two `addiu` by folding address computations the target performs, which is a
change in what work is done, while being one instruction closer by coincidence
of the totals.

This is the third time on this entry that a count has pointed the wrong way, so
it is worth stating as a rule for the next attempt: **on this function, rank by
multiset distance and use the instruction count only as a tiebreak.**

**The addressing check came back negative.** `lui` never appears in the
differences, so declaring the two arrays plainly already produces the target's
addressing.
