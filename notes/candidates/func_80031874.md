## Four things the shape needed

**The profile is `no_strength_reduce`, and it is the only one that reaches the
instruction count.** Every other profile is seven instructions long. Seven
matched functions already use it, so it is not an outlier here.

**`obj->field_4` is read once into a local.** It is stored into both sprites;
reading it twice costs an instruction and a load-delay `nop`.

**The record block's `+4` belongs to the offset, not the base.** Written
`D_8009B2FC + (kind * 0x2D4C + 4)` GCC emits `sll` / `lw` of the pointer /
`addiu 4` / `addu`, which is retail's order; written
`D_8009B2FC + kind * 0x2D4C + 4` the `addiu` moves after the `addu`.

**The three byte-table reads keep the base first.** `*(D_8009B2FC + value +
0x606A)` gives `addu $v0, $v0, $s2` with the pointer first;
`D_8009B2FC[value + 0x606A]` groups the index with the constant and comes out
`addu $v0, $s2, $v0`. Three positions, and the same `expand_expr` association
rule recorded for `func_8004C114` and #2073.

## What is left is entirely the prologue

loop - all four `func_800316F0` calls, the two `Text_EncodeDecimalDigits`

the `0x1F800000` text pointer at `0x0090`; retail materialises it at `0x00e8`,
