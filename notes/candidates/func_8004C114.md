The sequencer's MIDI channel-event dispatcher, between
`sound_sequence_meta_events.c` and `func_8004C420.c`. It takes the running
track record, a status byte, and two data bytes, and dispatches on the status
nibble: `0x80` and a zero-velocity `0x90` go to `func_8004B374`, a non-zero
`0x90` to `func_8004ADE8`, `0xC0` to `func_8004B6E8`, `0xE0` to
`func_8004B70C`, and `0xB0` falls through to `func_8004B49C` after two
controller-specific side effects.

Controller 99 is a save/restore pair over the 44-byte track records at
`0x518` in `D_8009B458`. Value 20 pushes: each record copies `+0x24`, `+0x29`
and `+0x18` forward into `+0x25`, `+0x2A` and `+0x1A`, and the two words at
`+0x00` and `+0x1C` into `+0x04` and `+0x20`, then the state's `0x7F0` word
goes to `0x7F4`. Value 30 pops the same fields back and decrements the track's
`+0x26` depth counter while it is below 127. Controller 6 writes the data byte
into every record's `+0x53E` when the selected channel's `+18` byte is 20.

### What the shape needed

- **The dispatch is a `switch` on `status & 0xF0`.** GCC builds the retail
  decision tree — compare against `0xB0`, then `slti 177` to split the
  remaining four cases — only from a switch.
- **The `0x7F8`-is-zero exits are `else` arms, not early returns.** Written as
  `if (... == 0) { track[38] = data2; return; }` GCC makes the return block the
  fall-through and pushes the loop out of line; retail has the opposite. An
  `else` after the loop reproduces the retail layout and is worth two
  positions.
- **The state pointer is read once per iteration and used for both the record
  address and the loop bound.** Reading `D_8009B458` separately for
  `p = (u8 *)D_8009B458 + off` and for `D_8009B458->field_07FA` gives two loads
  per iteration, because the stores through `p` may alias the pointer itself
  and block the CSE. One local read at the top of the body serves both and
  takes the build from eleven instructions long to four.

- **The state read is rotated.** It has to sit *between* the byte copies and
  the word copies, with the pointer cached before the loop so the record
  address uses the previous iteration's value. At the top of the body the load
  feeds the very next instruction and MASPSX inserts a `nop`; rotated, the two
  following `lw`s fill the delay, exactly as retail.
- **The counter is incremented in the loop condition.** `} while (++i < ...)`
  puts the `addiu` between the bound load and the `slt`, filling that load
  delay too. With `i++` in the body GCC hoists it and the `nop` comes back.

Those two together take the build from eleven instructions long to two.

- **The pre-loop tests must read through the same local the loop uses.**
  Testing `0x7F8` and `0x7FA` on `D_8009B458` directly while the loop keeps its
  own `state` local gives two pseudos and a `move` at loop entry. Hoisting one
  read before the tests and using it for both closes that and the two remaining
  instructions at once: the build goes from 197 instructions and 162 differing
  positions to an exact 195 at 79.
- **The controller-6 loop needs the same treatment.** Left reading the global
  inline it loses three instructions; routed through the shared local with a
  reload after the store it matches the other two loops.
- **The entry copies are pinned.** Retail binds the track record to `$t5`, the
  channel to `$t4` and the first data byte to `$t3`; unpinned this build uses
  `$t4`, `$t3` and `$t5`, which alone is worth 39 positions.
- **Two small orderings.** The halfword copy goes before the state reload, and
  the `0x7F8`-is-zero fallback reads the track word before storing the byte.

### What is left

Nineteen words in three groups, none of them structural.

Twelve are register naming: retail keeps the record byte offset in `$t2` in the
save/restore loops and in `$v1` in the controller-6 loop, where this build uses
`$a2` throughout, and the controller-6 loop addresses the record from `$a0`
rather than the cached pointer.

Four are the halfword copy's store, which retail emits *after* the state
reload while its load stays hoisted with the byte reads. Moving the whole copy
after the reload puts the load back too and costs six more; hoisting only the
load through an explicit temporary costs twenty-six. No spelling found so far
separates them.

The last three are the `0x7F8`-is-zero fallback, which retail addresses from
`$t5` where this build uses a copy in `$a0`.

the state pointer cached once before each loop and read at the top of each
