Advances the screen fade one frame. `src/game/fade_draw_overlay.c` already
names this function as the one that steps the state it renders, and declares it
as taking a `u8 *`, so the parameter keeps that type here rather than the
struct.

`D_800E9EC8` is the resident `FadeTransitionState` from `src/game/fade.h`,
whose layout already pins every offset this function touches: the tint bytes at
0 to 2, the current and target levels at 4 and 5, the flag byte at 6 and the
per-frame step at 7. `D_800E9ECC` is the level field of that same record but is
reached through its own symbol, which is what produces the separate `lui` and
`%lo` pair for the final store instead of a displacement off the held base.

## What reached distance 3

**The unequal-level arm sits out of line.** The target branches away on
`bne $s0, $a0` to a block placed after the whole equal-level path and falls
through to the common case. Writing it as `if (lvl != tgt) { ... return; }`
inlines that arm, inverts the branch and scatters the block: opcode distance 4
and positional diff 46. Reaching it by `goto` past an explicit `return`
reproduces the target's layout and takes the positional diff to 4.

**The step is a byte times a word.** The per-frame step at offset 7 multiplies
`D_8009B0D8`, and the result feeds both the add and the subtract arms, so it is
computed once before the level comparison.

**Both clamp arms compare in opposite directions.** After adding, the target
re-tests `lvl < tgt`; after subtracting, it tests `tgt < lvl`. Writing both as
the same comparison costs the `slt` operand order.
