## `func_8002F630` at 0x8002F630

`gcc_2_8_1_g8_split`, 192 of 192 instructions, 12 differing non-relocation
words, all inside one twelve-instruction scheduling window at the end of the
function.

The script overlay's screen-open state handler, the function after
`func_8002F4C0` and before `script_control_commands.c`. On the first entry it
requests the 8103/50 async transfer with `func_8002F4C0` itself as the
completion callback and consumes two bytes from the script cursor as a
little-endian halfword. Then, if the screen is not already up and neither the
`0x02000030` bits of `D_8009B0F4` nor `D_8009B134` are set, it raises the
`0x4000` flag, clears bit 6 of the current display object, resets the object
table at `D_800EB0F8`, and builds four display objects: a text panel through
`func_800428A8` with the `D_801AF000` font, two 240-wide strips laid out with
`func_80040510`, and a backdrop whose colours and corner it writes directly.
When the screen is already up it polls `func_8004703C`, and on bit 7 clear it
fades out, re-raises bit 6, destroys the backdrop and clears the flag.

All six canonical attempts were automatic first-pass output that differed at
`+0x0`: the frame was 40 bytes against retail's 72, so none of them had
recovered the seven saved registers. This is the first reconstruction.

### What the shape needed

- **`D_8009B0F4` and `D_8009B134` must not be reached through `$gp`.** Retail
  uses `lui`/`lw` pairs for both. Under `-G8` a plain `extern s32` collapses to
  one `gp`-relative instruction each; the `__attribute__((section(".data")))`
  idiom restores the two-instruction form. This single change takes the build
  from 146 differing positions to 18, because it is also what pushes the
  register pressure up to the seven saved registers the six attempts were
  missing.
- **The profile is `gcc_2_8_1_g8_split`.** On plain `gcc_2_8_1_g8` the same
  source is 161 differing; the split addressing is needed for the
  `D_800EB0F8` object table, whose `%hi` is kept in `$s0` and reused for the
  first table store while the full pointer in `$s3` serves the other two.
- **The backdrop is a separate local from the three display objects.** Retail
  puts it in `$s0`, reusing the register that held the `%hi` and is dead by
  then. Reusing the same `obj` variable for all four keeps it in `$s5` and
  costs three positions.
- **The corner colour is staged in a local.** Written inline, GCC hoists the
  `0x00FFFFFF` pair instead and the whole constant block rotates.

### What is left

Twelve words, all between `+0x234` and `+0x278`, and they are one rotation of
a single window rather than twelve independent differences:

```

           / ori v1,v1,0xffff / sw v1,60 / sw v1,68 / lui v1,0x6000
           / sw zero,40 / sw a0,64 / sw s0,888(gp)
  build    ori v1,v1,0xffff / li v0,320 / sw v0,48 / lui v0,0xf0 / sw v0,56
           / sw v1,60 / sw v1,68 / sw zero,40 / sw a0,64 / lw v0,4(s0)
           / lui v1,0x6000
```

Retail reads `panel[4]` early, right after the `+0x38` store, and defers the
second half of the `0x00FFFFFF` constant past it; this build does the reverse.
The last word is the same shortage seen from the other end: retail puts
`sb $s4, D_800E9ECF` in the `jal func_80015998` delay slot and this build
leaves a `nop` there.

Crossed without closing it: staging the `panel[4]` read in a local at three
points, which restores the constant order but loses the read position again
and goes back to sixteen; all orderings of the six backdrop stores; moving
`D_8009B280 = panel` before the `+0x40` store; writing the flag constant
inline rather than through `four`; and every `gcc_2_8_1_*` profile.
