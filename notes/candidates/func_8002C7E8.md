## `Duel_CheckRitual` at 0x8002C7E8

`gcc_2_8_1_g0`, 83 instructions against a target of 84, opcode distance 1.

Resolves a ritual summon: given a ritual card id, find its recipe, check the
active player's five-card zone for the three required materials, consume them,
and report the resulting monster.

`gDuel_awRitualData` is a flat table of 10-byte records walked as a `u16 *`
cursor, terminated by a zero first halfword. Each record is the ritual id, then
three material ids, then the result id at offset 8. Walking it as halfwords
rather than as a struct is what produces the `p += 5` stride and lets the tail
read the result as `p[3]` off the already-advanced material cursor, which is
how the target keeps the record pointer live to the very last instruction.

`D_8009B1D5` selects whose zone is searched: element 5 or element 20 of
`D_801A7AD8`, whose stride of 0x1C the `a3 * 8 - a3 << 2` sequence encodes.
Slots are eligible only when bit 0x8000 of the halfword at 0x16 is set; the
five results are collected into a local array, with each matched entry cleared
as it is consumed so one card cannot satisfy two materials.

Four shape facts carried this from distance 5 to distance 1.

**The ritual id parameter is not `u16`.** The target compares the table
halfword against `$a1` raw. Declaring the parameter `u16` adds an
`andi $a1, $a1, 0xffff` narrowing that the target does not perform, so the
parameter is a full word and the `u16` load supplies the zero extension.

**The zone selector defaults to 5.** Written as `if/else` GCC picks the
opposite branch polarity. Written as `base = 5;` followed by
`if (D_8009B1D5 != 0) base = 20;` it emits `beqz` with the 5 in the delay slot,
matching the target.

**The candidate array base must be hoisted.** The target computes
`$t5 = $sp + 0x10` once before the outer loop and re-copies it per iteration;
indexing the local array directly makes GCC rematerialize `sp + 16` inside the
loop instead. An explicit pointer variable initialized outside the loop fixes
both the placement and two copies.

**The output list is written through a walking pointer,** not `found[j]`, which
is what yields the `addiu $t2, $t2, 0x4` advance.

## What is left

One instruction: the `addu $a2, $t0, $zero` at the top of the inner scan. The
target keeps three live pointers there, a hoisted base, an induction variable,
and a body copy; every spelling tried collapses the last two into one register.
Confirmed against six spellings, an explicit temporary read before the compare,
the increment moved into the `for` clause, `&slot[1]` in place of `slot + 1`,
and clearing the consumed slot through the copy rather than the cursor so the
copy is live on exit. All produce the identical 83-instruction build. Hoisting
the increment above the load does reach 84 instructions but fills the delay
slot with the increment instead of the target's `nop`, scoring distance 2, so
it is a worse base despite the exact length.

Every other instruction is positionally identical to the target.
