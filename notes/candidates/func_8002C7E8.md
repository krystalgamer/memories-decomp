## `Duel_CheckRitual` at 0x8002C7E8

`gcc_2_8_1_cc_g8_as_g0_split`, 84 instructions against a target of 84, opcode
distance 0, positional opcode diff 0. Seven words differ, and all seven are one
consistent register swap.

Resolves a ritual summon: given a ritual card id, find its recipe, check the
active player's five-card zone for the three required materials, consume them,
and report the resulting monster.

`gDuel_awRitualData` is a flat table of 10-byte records walked as a `u16 *`
cursor, terminated by a zero first halfword: ritual id, three material ids,
then the result at offset 8. Walking it as halfwords rather than as a struct
produces the `p += 5` stride and lets the tail read the result as `p[3]` off
the already-advanced material cursor, which is how the target keeps the record
pointer live to the last instruction. `D_8009B1D5` selects whose zone is
searched, element 5 or element 20 of `D_801A7AD8`, whose 0x1C stride the
`i * 8 - i << 2` sequence encodes. Slots are eligible only when bit 0x8000 of
the halfword at 0x16 is set, and each matched entry is cleared as it is
consumed so one card cannot satisfy two materials.

## What moved this from distance 1 to positionally exact

**The inner scan is an indexed read whose consumed slot is cleared by the same
index.** Writing `card = first[i]` with `first[i] = 0` on the match path lets
strength reduction build a separate address register, which is what produces
the copy at the top of the loop and the `addiu $t0, $a2, 0x4` advance in the
branch delay slot. Every pointer-cursor spelling collapses those two registers
and lands one instruction short. A post-increment `*slot++` does create the
second register but computes the advance next to the load, filling the load
delay slot the target leaves as a `nop`; that reaches distance 0 but keeps two
positions wrong. The placement is invariant under `-fno-schedule-insns` and
`-fno-schedule-insns2`, so it is source shape, not a scheduling flag.

**The zone index and the collect-loop counter are one variable.** The target
holds 5 or 20 in `$a3` and then reuses `$a3` as the counter. Declaring a
separate `base` keeps them in different registers and costs eight words.
Assigning into `i`, using it, then resetting it fixes the whole
`sll`/`subu`/`sll`/`addu` block.

**Both loop counters are pre-initialized before their `for`.** A bare
`for (j = 0; ...)` emits the zero after the surrounding pointer setup; the
target emits it first. An explicit `j = 0;` ahead of the setup reorders the
block and, because register assignment follows those definitions, also corrects
the `$t2`/`$t3` split in the match tail.

**The cands cursor is an explicit pointer advanced before the card pointer.**
That orders `w` at 4 and `c` at 0x1C into the positions the target uses.

## What is left

Seven words, one binary allocation choice: the target puts the card walker in
`$a1` and the cands cursor in `$v1`, this build puts them the other way round.
Nothing else differs, and the strides are already paired to the correct
positions.

Swept without moving it: five inner-loop spellings, six collect-loop spellings,
all 120 permutations of the pointer declarations, every GCC 2.8.1 profile, both
scheduling flags, indexing the card array so both cursors become induction
variables, and hoisting the eligibility test into an if/else. The indexed
collect form ties on the word count but pairs the strides to the wrong
positions, so it is a worse base despite the equal score.

#include "../types.h"

typedef struct {
    u32 w0;
    u8 pad4[0x8];
    s16 id;
    u8 padE[0x8];
    u16 flags;
    u8 pad18[0x4];
} Card;

typedef struct {
    u32 w[3];
    s32 unkC;
} RitualOut;

extern u16 gDuel_awRitualData[];
extern u8 D_8009B1D5;
extern Card D_801A7AD8[];

u16 Duel_CheckRitual(RitualOut *out, s32 ritualId)
{
    Card *found[3];
    Card *cands[5];
    Card *card;
    Card **first;
    Card **dst;
    Card **w;
    Card *c;
    u16 *p;
    u16 *q;
    s32 i;
    s32 j;

    p = gDuel_awRitualData;
    while (1) {
        if (p[0] == 0) {
            return 0;
        }
        if (p[0] == ritualId) {
            break;
        }
        p += 5;
    }

    i = 5;
    if (D_8009B1D5 != 0) {
        i = 20;
    }
    c = &D_801A7AD8[i];
    i = 0;
    w = cands;
    for (i = 0; i < 5; i++) {
        *w = 0;
        if (c->flags & 0x8000) {
            *w = c;
        }
        w++;
        c++;
    }

    p++;
    j = 0;
    first = cands;
    dst = found;
    q = p;
    for (j = 0; j < 3; j++) {
        for (i = 0; i < 5; i++) {
            card = first[i];
            if (card != 0 && card->id == q[0]) {
                goto matched;
            }
        }
        return 0;
matched:
        *dst++ = card;
        first[i] = 0;
        q++;
    }

    if (out != 0) {
        for (i = 0; i < 3; i++) {
            out->w[i] = found[i]->w0;
        }
        out->unkC = 0;
    }
    return p[3];
}
