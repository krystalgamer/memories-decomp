## `func_8005C1F4` at 0x8005C1F4

`gcc_2_8_1_g8_split`, 94 instructions against a target of 96. Everything except
one four-instruction window in the ring-slot address setup is identical,
including all three call sequences, the signed `% 4` advance, the eight-byte
unaligned header copy, and both branch delay slots.

The `DecDCTout` callback, registered by `src/game/func_8005B8A0.c`, which is
the sibling to copy conventions from: it declares `D_8009B498` as `u8 *` and
adds large literal offsets to it directly.

Each call copies the current strip header into the ring slot for
`D_8009B067`, hands that slot and the matching frame buffer to `LoadImage`,
advances the index modulo four, then accumulates the strip height. While the
accumulated height is still short of the frame height it queues the next
decode with `DecDCTout`; otherwise it raises `D_8009B062`.

### Shape facts

**The header copy is one eight-byte block move, not two four-byte ones.**
Retail issues both `lwl`/`lwr` pairs and only then both `swl`/`swr` pairs, with
no `nop` between them, which is a single `movstrsi` of eight bytes at alignment
one. A `typedef struct { u8 b[8]; } Bytes8;` and one assignment reproduce it
exactly; two `Bytes4` assignments interleave load and store and cost two
`nop`s.

**`D_800F5D44` must not be reached through `$gp`.** Retail uses
`lui`/`lw` and `lui`/`sw` pairs. Under `-G8` a plain `extern s32` lands in
small data and collapses to one `gp`-relative instruction each, losing two
instructions. The sibling's `__attribute__((section(".data")))` idiom forces
the two-instruction form, and it also lets GCC fill the
`beqz` delay slot with the first half of the `0x42400` constant exactly as
retail does.

**Offsets are written absolutely from the base pointer.** Writing
`*(u16 *)(D_8009B498 + 0x42428)` and letting GCC split `0x42428` into the
`lui $s0, 0x4` register plus a `0x2428` displacement reproduces retail
throughout. An explicit `h = D_8009B498 + 0x40000` window local also reaches
the right displacements but computes the window pointer too early and shuffles
the whole address block.

**Both large index scalings keep the constant on the index side.** Retail
computes `base + (idx * 8 + 0x42400)` and `base + (idx * 0x2D00 + 0x37000)`,
not `(base + idx * 8) + 0x42400`. The parentheses are load-bearing and worth
two instructions.

**The profile is `gcc_2_8_1_g8_split`.** On plain `gcc_2_8_1_g8` this same
source is fifteen instructions long and distance 20, because the address
constants are materialised differently. The neighbouring
`func_8005BFC8` and `func_8005C374` both use `gcc_2_8_1_g8`, so the usual
inheritance would have picked the wrong one here; `func_8005B8A0`, the
registrar, is the sibling that uses `_split`.

### What remains

Retail computes `idx * 8` twice:

```
  22  sll   a0,v1,0x3         ; for the LoadImage rectangle
  23  addu  a0,a0,v0          ;   + 0x42400
  24  addu  a0,a2,a0          ;   + base
  ...
  31  move  v0,v1             ; save the index, v0's constant is now dead
  32  move  v1,a2             ; a base copy that is about to be destroyed
  33  sll   v0,v0,0x3         ; the same shift again
  34  addu  v0,v1,v0          ;   + base
  35  addu  v0,v0,s0          ;   + 0x40000, the copy destination
  36  addu  v1,v1,s0          ;   the copy source
```

This build CSEs the two shifts into one and needs only one register copy, which
is exactly the two missing instructions. The two `move`s are register shuffles
freeing `v1`, so the recomputation looks like an allocation artefact rather
than a source-level distinction.

Explored without reaching it: the destination as `d = base + idx * 8` with the
`0x42400` displacement, as `base + idx * 8 + 0x40000` with a `0x2400`
displacement, stepped with `d = base; d += idx * 8;`, through a
`(Bytes8 *)base + idx` ring pointer, and through a second index local; the
`LoadImage` rectangle as an array index, from a pre-computed local kept live
across the copy, and re-read from `D_8009B067` (which buys the recomputation
but costs an extra `lbu`); a `u8` index; and every `gcc_2_8_1_*` profile.
