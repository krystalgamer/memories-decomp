## `func_80018608` at 0x80018608

`gcc_2_8_1_g8_split`, 224 of 225 instructions, opcode distance 1, 11 differing
positions. Written from scratch; there was no previous candidate.

The duel start-up state machine. On its first call it sets bit 0x8000 of
`D_8009B23A`, asks for the combined deck data, seeds the three halfwords at
`D_800F2848` with 0x4B0/0x358/0x16C0, ticks the display and moves to phase 2.
Phase 2 walks those three values down by 2, 2 and 0x10 per frame and snaps them
to 0x258/0x100/0x400 once the middle one falls to 0x400 or below, at which
point phase 3 starts. Phase 3 sets bit 0x80 of the phase byte once, arms the
message counter at `D_8009B162` with 2, points `D_8009B1B4` at the current
side's selection record and writes 0xAE into it, then waits for the counter to
drain before moving to phase 4. Phase 4 waits for the file transfer to go idle,
starts the BGM, populates the deck data, and averages the attack and defence of
both forty-card decks into the two rank records at `D_800E9FF0 + 0xE` and
`+ 0x2E`. Phase 5 clears the hand slots, records five empty slots, hands the
hand-object table to the side's selection record and returns the outer state to
3.

**Levers, in the order they paid.**

- *`-G8` with split addresses.* Every one-, two- and four-byte scalar the
  function touches (`D_8009B23A`, `D_8009B162`, `D_8009B174`, `D_8009B1D5`,
  `D_8009B1EC`, `D_8009B1B4`) is `%gp_rel` in the target, so the unit is `-G8`;
  `D_8009B0F4`, `D_8009B134` and `D_8009B36A` are `%hi`/`%lo` instead and so
  have to be declared as arrays of unknown size, which keeps them out of small
  data. `D_800F2848` is reached as `%lo(sym)($hi)` for offset 0 and through a
  materialised base for offsets 2 and 4, which is the `-mgas -msplit-addresses`
  shape, not the plain `-G8` one.

- *`D_800F2848` needs a pointer variable assigned before the outer `if`.* The
  target holds `%hi(D_800F2848)` in `$s2` and the full address in `$s1` across
  the whole function, and both are set in the entry block, before the flag
  test. A plain `D_800F2848[k]` reference in each arm rebuilds the address per
  block into a scratch register. Assigning `w = D_800F2848;` at the top makes
  the pair function-global and callee-saved. Offset 0 still has to be written
  as `D_800F2848[0]` rather than `w[0]`: the direct reference is what emits
  `%lo(sym)($s2)`, and it is also what stops the scheduler hoisting the
  `w[2]` load above the offset-0 store, which the target does not do.

- *Phase 2 reads and writes the three halfwords in place.* `w[2] -= 2;`
  `w[1] -= 0x10;` with the comparison written as `(s16)w[1] <= 0x400` after
  the store gives the target's load/load, `addiu`/`addiu`, store, sign-extend,
  compare, store-in-the-delay-slot order. Computing the two new values into
  locals first and storing them afterwards swaps the two loads and the two
  `addiu`s, whichever order the two statements are written in; the scheduler
  ranks the temporaries, not the source.

- *Every quantity used by both deck loops has to be a separate variable per
  loop, except the ones the target keeps in one register.* `atk`, `def`, `i`
  and `rec` are shared and land in `$t0`, `$t1`, `$a2`, `$a3` by global
  allocation. The card-stat value and the two `D_800E9FF0` base pointers are
  not shared: the target puts them in `$v1`, `$v1` and `$a0`, which are local
  allocations, so the source needs `stat`/`stat2` and `r1`/`r2` rather than one
  of each. One shared stat variable becomes a global pseudo, takes `$a0`, and
  pushes the masked value into `$v1` -- the exact inverse of the target -- and
  one shared base pointer permutes the whole loop assignment by one slot
  (`atk` to `$a3`, `def` to `$t0`, `i` to `$a1`, `rec` to `$a2`).

- *The rank record has to be reached through a base register, the selection
  record through a struct.* `*(s16 *)(D_800E9FF0 + 0xE)` folds the 0xE into the
  relocation and reuses that as the base for `+0x10`; assigning
  `r1 = D_800E9FF0;` first restores the target's `lui`/`addiu` and the 0xE/0x10
  displacements. The mirror case in phase 5 is the opposite: there the base is
  `sym + side * 0x70` and the target keeps the `+8` on the store, but
  `*(u8 **)(D_800E9F10 + side * 0x70 + 8)` re-associates the constant onto the
  symbol and emits `addiu $v1,$v1,%lo(sym)+8`. Casting to a struct whose member
  sits at 8 keeps the displacement on the `sw` and, unlike a pointer local,
  adds no pseudo -- which matters, because the pointer local also moved the
  address load after the `lbu` and away from the target's schedule.

**What is left** is one contiguous window of eleven positions, 0x80018778 to
0x800187AC, plus the empty delay slot at 0x8001879C that follows from it. Every
other instruction in the function matches the target in opcode and in register.

The window is the phase-4 guard and the BGM argument:

Two things, and the second is a consequence of the first two lines of it:

- The mask constant is allocated last here and first in the target, which
  pushes it to `$a0` and the two loaded words down to `$v0`/`$v1`, and the
  scheduler then hoists the second `lui` above the first `lw` to cover the load
  delay. Tried without moving it: both operand orders of the `|`, both operand
  orders of the `&`, the two loads read into locals before the test, `break`
  versus `return` versus wrapping the rest of the case in `if (... == 0)`,
  `u32`/`s32`/sized-array declarations for the two globals, and
  `gcc_2_8_1_g8_split`, `gcc_2_8_1_g8_split_comm`,
  `gcc_2_8_1_g8_split_no_strength_reduce`, `gcc_2_8_1_cc_g0_as_g8_split`.

- The `%hi(D_8009B36A)` in the target lands in `$a0`, the same register the
  `lhu` writes; here it lands in `$v0`. That single register is what fills the
  branch delay slot: `fill_eager_delay_slots` steals the first instruction of
  the not-taken thread, and it refuses when that instruction writes an argument
  register. Confirmed directly -- replacing the argument with a literal, so the
  first instruction after the branch is `li $a0, 0x1234`, reproduces the
  target's empty slot exactly. So the delay slot is not a separate problem; it
  closes by itself as soon as the `lui` is allocated `$a0`. Tried without
  moving it: the value read into a `u16` or `u32` local first, `*D_8009B36A`,
  a K&R declaration and a `u16` parameter for `SD_BGMPlay`, `D_8009B36A`
  declared `[]`/`[2]` (the latter puts it in small data and changes the
  addressing), and pinning a `u16 *` local to `$4`, which GCC folds away.
