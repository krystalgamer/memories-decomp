## `func_800482B0` at 0x800482B0

`gcc_2_8_1_cc_g0_as_g8_no_split`, 232 of 234 instructions, opcode distance 4,
78 differing positions. Written from scratch; there was no previous candidate.

The sound-effect voice allocator. It drops the request when the id has no entry
in the index table at `field_043C`, hands ids with bit 0x8000 set to
`func_800451E0`, and otherwise picks a voice three ways in turn: the low nibble
of `mode` asks `func_80047F38` for a keyed group and takes its lowest set slot;
the high nibble asks for the n-th voice already playing this id, found by
walking `SpuGetVoiceEnvelope` over the four slots and matching `voice_ids`; and
failing both, the rotating cursor at `field_0435` is walked twice, once
accepting only a silent voice and once accepting any voice whose recorded value
at `field_040C` is no higher than this request's. Every path ends in the same
`field_0435 = slot; func_8004803C(...)` call.

**Levers, in the order they paid.**

- *The shared call is written out at each site, not reached by `goto`.* Both
  early paths end in the same seven-argument call. A single labelled block
  reached by `goto` puts that block at the end of the function; writing the
  call out in each loop body lets cross-jumping merge the common suffix and
  places the merged block where the target has it, immediately after the
  0x8000 branch and before both loops. Worth 48 positions on its own,
  114 down to 66, and it is what puts the two spill slots at the target's
  0x22 and 0x28.

- *`mode` has to be copied into a local, and the copy has to be the first
  statement.* GCC leaves a stack-passed argument whose nominal and passed modes
  agree in its home slot: every use of the parameter then re-reads memory, and
  because the reads are byte and word loads each costs a delay-slot `nop` as
  well. `md = mode;` gives it a pseudo. Putting the assignment before the
  `field_043C` guard rather than after it is what moves the load into the entry
  block, where the scheduler covers its delay; after the guard the load sits in
  a later block and needs a `nop`. `value`, a `u8`, needs no such copy because
  the narrowing conversion already forces a pseudo.

- *The two spilled arguments are the ones with narrow types.* `volume` is `u8`
  and `pan` is `s16`, so they spill as `sb`/`sh` into compiler slots at 0x22
  and 0x28 exactly as the target does, while `pitch` stays raw in `$fp` and is
  sign-extended at each of its four uses. Declaring `pitch` `s16` instead of
  `s32` spills it as a halfword and moves `volume` into a register.

- *Both scan loops step two counters.* The envelope index is a plain `s32` and
  the slot index is a `u8`, and the target masks the second at every use, so
  they cannot be the same variable even though they hold the same value.

- *The cursor is bumped as two separate read-modify-writes.* The target reloads
  `g_SDValue` between `field_0435 + 1` and `field_0435 & 3`; writing it as one
  expression folds them and drops a reload. This is the byte-store CSE
  invalidation already recorded for `func_8004803C`.

**What is left** is four opcodes: one `andi`, two `addu`, and one surplus
`nop`. All three come from the same place.

- *The missing `andi` is the loop-2 id comparison, and the cast that produces
  it costs more than it is worth.* The target compares
  `g_SDValue->voice_ids[slot]` against `(u16)id` recomputed inside the loop:

  ```
      lhu   $a0, 0x404($v0)
      andi  $v0, $s4, 0xFFFF
      bne   $a0, $v0, .L80048444
  ```

  Writing the cast makes the `andi` a loop invariant, and GCC hoists it into
  the preheader as `andi $s5, $s4, 0xFFFF`. That is a tenth long-lived value
  against nine callee-saved registers, so `mode` loses its register again and
  the function goes back to distance 18. The stored source therefore drops the
  cast and compares against the `s32` parameter, which is one instruction short
  here (a delay-slot `nop` stands where the target has the `andi`) and is only
  equivalent for ids below 0x10000, which the 0x8000 guard above already
  guarantees.

  Crossed without stopping the hoist: `for`, `while`, `do`/`while` and a
  `goto` loop; the condition split into nested `if`s; the operands reversed;
  the loaded halfword read into a local first; `u16`, `s32` and `u32` for
  `id`; `register` on the parameters; and, at the compiler,
  `-fno-schedule-insns`, `-fno-schedule-insns2`, `-fno-expensive-optimizations`,
  `-fno-force-mem`, `-fno-strength-reduce`, `-fno-rerun-cse-after-loop`,
  `-fno-cse-follow-jumps`, `-fno-thread-jumps`, `-fno-caller-saves`,
  `-fno-function-cse`, `-fno-peephole`, `-fno-delayed-branch` and `-fno-inline`,
  none of which changes the count of `andi ...,0xffff` in the output.

- *The two missing `addu` are uncoalesced parameter copies.* The target copies
  the id twice, `addu $t0, $a0, $zero` then `addu $s4, $t0, $zero`, and uses
  `$t0` for the 0x8000 test and `$s4` everywhere else; it also copies the
  loaded `mode` with `addu $s6, $a1, $zero` and still uses `$a1` for the
  `& 0xF` test afterwards. Both look like a parameter and a local copy of it
  being live at once. Introducing that split in the source (a separate `arg0`
  used only for the 0x8000 test, a separate `mode` used only for the `& 0xF`
  test) does not reproduce it: GCC copy-propagates and coalesces, and the
  output is unchanged at distance 4.
