### What the shape needed

- **Branch polarity is the dominant lever.** GCC 2.8 falls through to the
  *then* arm and branches to the *else*, so every retail `if` whose branch
  target is the larger block has to be written with its condition inverted
  relative to the obvious reading. Writing
  `if (*(s16 *)(p + 64) != 0) { reuse } else { build }` rather than the
  natural `== 0` form takes the build from 191 differing positions to 87.
  The same inversion applies to the countdown tests: `if (n <= 0) ... else if
  (n >= 20) ... else ...` reproduces retail's `bgtz`/`bnez` pair, where
  `n > 0` / `n < 20` produces `blez`/`beqz` and shifts every block.
- **`D_8009B0D8` must not be reached through `$gp`.** Retail uses
  `lui`/`lhu`; the profile is `gcc_2_8_1_g0`, the same as the neighbouring
  `func_8003AD6C.c`, which puts nothing in small data.
- **The shared colour byte needs a temporary.** `obj[12] << 5` written twice
  is read twice, because the intervening store to the other object may alias
  it. One local read serves both stores and saves three instructions.
- **`0xF7FFFFFF` is a local.** Retail keeps it in `$s0` across both object
  updates, which only happens when it is a variable rather than two inline
  constants.

- **The shared exit block sits between the two arms.** Retail reaches
  `p[51] = 0` with a `j` from the zero-countdown arm and *falls into* it from
  the `func_80039FD4` arm, so the block is emitted after that arm and before
  the fade block. Neither duplicating the store in both arms (GCC will not
  cross-jump the pair, one instruction long) nor hoisting it after the whole
  chain (the block lands after the fade arm, which then needs a jump over it,
  two instructions long) reproduces that. Writing the fade arm as
  `if (n < 20) goto fade;` with `done:` and `fade:` as explicit labels puts
  the exit exactly where retail has it and closes both instructions: the build
  goes from 47 differing positions at +2 to 17 at the exact count.
- **The second object's `+0x46` store follows its `+0x4A` read.** Assigning
  `obj2->h70` before `obj2->h74` lets the load hoist the way retail schedules
  it.
- **`0x8FFFFFFF` is a local too.** Staged like the other mask it is
  materialised before `0x00808080`, which is retail's order; inline it comes
  second.
