## `func_80060E70` at 0x80060E70

`gcc_2_8_1_cc_g0_as_g8`, 102 instructions against a target of 102, opcode
distance 2, positional opcode diff 8.

Builds the seven text boxes for one duel hand row. The row record is
`D_801A8000[idx]`, a 24-byte struct holding a display object pointer, an x/y
pair, the flag, and a seven-slot `u16` array of card ids. Each iteration copies
the entry id into that array, picks a box style, creates the box, positions it
at a 0x16 pitch, and hands it to `func_80039A14`.

The style starts as the id itself, so an empty slot yields style zero and the
whole lookup block is skipped. For a live card it is `0x18`, or `0x1A` when the
row flag is set, plus one more when the card type in the top five bits of
`gDuel_adwCardStats[id - 1]` is at least 0x14. That type is extracted with an
arithmetic shift, which is why the table is `s32`.

The `Box` struct, the `TextBox_Create` signature and `func_80039A14` come
unchanged from the matched `src/game/card_list_text_boxes.c`.
`gDuel_wSelectedCardID` needs `section(".data")` here for the `$at` macro form.

## What moved it from distance 6 to distance 2

**The entry list is walked by two `u16 *` cursors, and the first is the
parameter itself.** The target copies `$a0` into `$s3` at the second
instruction of the prologue, alongside the register saves, then derives
`$s1 = $s3 + 2`. Using a separate local for the id cursor emits that copy late,
in the middle of the setup block instead. Advancing the parameter directly and
deriving only the flag cursor from it reproduces the prologue and takes the
positional diff from 16 to 12.

**The row's id array needs its own cursor.** Writing `s->fA[i]` lets GCC fold
that array into the loop's induction variable, which frees a callee-saved
register; GCC then spends it hoisting `&gDuel_adwCardStats` out of the loop.
The target has no register to spare and rematerialises that address inside the
loop on every iteration. Adding an explicit `u16 *` cursor restores the
pressure, removes the hoist, and takes distance from 3 to 2 with the length
back to exactly 102.

**The profile flips with that change.** On the previous base every `_split`
profile won and the plain ones were far behind. With the cursor in place the
non-split profiles are the only ones reaching the exact length, and `_split`
goes to 104. Profile choice had to be re-swept after the structural change
rather than inherited.

Loop spelling is not a live axis here: `for`, `while` and `do`/`while`, and
initialising the pitch accumulator from zero or from the counter, all
canonicalise to the same code.

## What is left

Eight positions. The largest is the pair of addresses around `D_801D5608`: the
target rematerialises `%hi(D_801D5608)` inside the loop for the `[0]` store but
reaches `[1]` through a register held since before the loop. Two forms for one
symbol in one block suggests the two words are reached through different
declarations rather than one array, which is the next thing to try. The rest is
one redundant `move`, and the id cursor being set up as `s + 0xA` where the
target keeps the row base and folds `0xA` into the displacement.
