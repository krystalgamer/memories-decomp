differing positions**, down from 62, all register names: the slot index and the slot

The model animation switch, next to `func_800577B0`. With `anim == -1`
it clears the pending flag and marks every attached part's frame
(+8 in the part record) as 0xFFFF. With `anim == 0` it flushes the
current animation: for every part whose map entry for the current
animation is valid it copies three or five words (five when the part's
bit in the +0xBEC mask is set) from the animation data at +0xDDC into
the frame buffer at +0xDE0. Any other animation is selected: the mode
byte is set to 2 unless it is the slot's default animation, a zero-length
entry is refused, a running animation is flushed first (only when the
flag argument allows it), mode 7 is set for the default or the 0x309
model, the current animation is recorded, a re-selection just re-queues
through `func_800597C8`, and otherwise the pending flag is raised and
every part gets its frame index and its first frame copied in.

**What the shape needed.**

- *The three cases are a `switch` on the animation* (cases -1 and 0,
  then default), which gives the two `beq`/`beqz` dispatch tests and the
  jump to the default block.
- *A slot struct with every field the function touches* (parts table,
  animation map as `u16 [11][58]`, entries, bit mask, the three pointers
  and the state bytes), so every access is off the one slot register;
  casting the pointer per access makes the loop optimizer hoist the cast
  as an invariant into a second register.
- *The bit test is written as the manual signed divide:* `t = i; if (i <
  0) t = i + 7; count = 3; t >>= count;` and `i - (t << count)`. Written
  as `i / 8` and `i % 8` the shifts are immediates; retail shifts by the
  register that holds the word count, which cse only produces when the
  count is assigned in the join block after the sign adjust.
- *The part walks step the pointer* (`parts++`) with the pointer
  increment before the counter increment in the `for` header, which puts
  the counter increment in the count load's delay slot; the other order
  hoists it into the part load's delay slot and costs a `nop`.
- *The map entry is read before the 0xFFFF test with its source address
  computed from it,* as retail does even for skipped entries.

**Where the residual is.** Global allocation orders the word count
(16 references over 38 instructions) before the slot pointer (44 over
153), so the count takes `$s1` and the pointer `$s2`; retail has the
pointer in `$s1` and the count sharing `$s2` with the index. Crossed:
the count and shift as one or two variables, the bit test through
`/ 8` and `% 8`, indexed part access, and `do`/`while` walks.

### From 62 to 4: four pins and one variable split

Every one of the 62 was a register name at the right position, which is the
*allocation* class - reachable by constraining registers, unlike a placement
disagreement. The steps, each measured:

- *Pin the slot pointer `m` to `$17`.* The slot index and the slot pointer were
  `$s1`/`$s2` the other way round. Pinning only the pointer swaps the pair;
  62 to **27**. Pinning the index as well costs 175, so only one side of the
  swap should be constrained - the allocator then does the right thing with the
  other.
- *Name the index offset and pin it to `$2`.* With `m` pinned, GCC computed the
  whole `index * 0xE20` chain directly into `$s1` where retail computes it in a
  temporary and only then forms the pointer. Writing
  `off = index * 0xE20; m = (AnimSlot *)((u8 *)D_800F2C40 + off);` with `off`
  pinned gives 27 to **22**. The unpinned form is neutral, so it is the register
  and not the naming.
- *Name the table base and pin it to `$3`.* Same in-place problem one level up:
  GCC materialised `D_800F2C40` into the pinned `$s1` rather than a temporary.
  A block-scoped `register u8 *tbl asm("$3") = (u8 *)D_800F2C40;` gives 22 to

- *Pin the sign-adjusted bit index `t` to `$2`*: 18 to **10** on its own, and
  with the base named, **6**.
- *Split `entry` into one variable per switch case.* Retail holds the map entry
  in `$a0` in the `case 0` walk and `$v1` in the `default` walk. One
  function-scope variable is one pseudo and therefore one hard register, so it
  cannot do that; declaring `s32 entry;` separately inside each case gives 6 to

**This is the mirror image of the `func_80045C98` match.** There, two locals
spelt as separate stages of one chain had to become *one* variable, because
retail allocated them to one register. Here, one local used in two independent
walks had to become *two*, because retail allocated them to two. The diagnostic
is the same in both directions: **count the distinct hard registers retail uses
for a value, and make the source have that many variables.**

All four pins are load-bearing. Removing them one at a time costs 49, 9, 4 and
12 positions respectively, and every pair is worse than the whole set.
